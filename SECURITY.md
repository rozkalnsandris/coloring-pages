# Security Policy

## Supported version

Security fixes are applied to the current production version from the `main` branch.

## Reporting a vulnerability

Please do not disclose exploitable security issues, credentials, tokens, personal data, or other sensitive details in a public issue.

If GitHub private vulnerability reporting is available for this repository, use **Security → Report a vulnerability**.

If private reporting is not available, open a minimal public issue stating that you need to report a security vulnerability privately, without including exploit details or sensitive information. The repository owner will provide an appropriate private reporting path.

Include, when safe to do so:

- the affected component or URL;
- a concise description of the impact;
- reproducible steps with secrets and personal data removed;
- the affected commit or version, if known;
- any suggested mitigation.

Please allow time for investigation before public disclosure.

## Scope

This policy covers the source code and repository-managed configuration for Ausmalwiese. Production host, Cloudflare, credentials, private content stores, and other infrastructure have separate operational boundaries and must not be probed without explicit authorization.
