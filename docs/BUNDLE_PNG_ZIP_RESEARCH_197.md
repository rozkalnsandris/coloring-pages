# Free thematic PNG ZIP sets — research decision (#197)

Status: **design/research only**. No ZIP, source code, user interface, data, payment, repository configuration, publication or runtime change is authorized by this document. Current source snapshot: `coloring-pages@e6eff3ff861faa4be92abfc4ef6bde35f2bfc66f` (2026-10-22). The proposal is not evidence that any proposed bundle exists or that referenced pages are licensed for republication.

## Decision

**GO for a free, fixed editorial set (initially 10 A4 print sheets) with a ZIP assembled offline by a separately approved, trusted publisher from currently published public `print.png` bytes. NO-GO for payments or visitor-generated 30-page ZIPs in the MVP.** Keep every individual coloring page available through the existing gallery → detail → print flow. A static set page can list selected already-published activities now, but the **ZIP download CTA must be disabled or absent until the exact verified archive is actually available**.

A ZIP is a new artifact, distinct from the incoming Chat draft ZIP used by protected ADMIN. Never pass a bundle ZIP back into ADMIN as a publication activity; it contains already-published **full-resolution print outputs**, not artwork drafts. Do not copy the private `originals/<id>/source.png` into a public archive.

The existing `print.html` handles the `pages[]` of **one catalogue activity**. It is **not** a cross-activity compositor. Therefore the MVP offers existing per-activity print links and one full-resolution PNG ZIP when available, but does **not** claim one-click printing of ten distinct IDs. Shared future export work belongs with #206 (five-A4-sheet interactive basket); #199 (book) and #203 (Kita sets) should reuse a reviewed common selection/ZIP contract, not create independent packers.

## Options matrix

| Option | Main benefit | Cost / failure mode | Verdict |
| --- | --- | --- | --- |
| Editorial static list, existing detail links only | No ZIP, no new runtime; easy first content curation | Does not provide one-file download | Safe fallback, not complete ZIP MVP |
| In-browser ZIP from public PNGs (`fetch` + audited, locally bundled ZIP library, `STORE`) | No permanent archive stored on server | All fetched input bytes **plus** generated Blob often reside in mobile memory; browser compatibility and cancellation/cleanup tests required | Defer; consider for <=5-sheet basket #206 only after measurements |
| **Prebuilt immutable ZIP, generated by a trusted offline publishing step** | One simple download; no user-state backend, no expensive compression on each request | Additional disk/CDN traffic, operator integrity gates, update/retirement process and separate LIVE authorization | **Recommended for fixed free 10-sheet bundles** |
| ZIP built per request by a new Worker/RPi5 endpoint | Flexible selections | Runtime CPU/bandwidth/abuse concerns, retries, request size/time limits, state and operations | Reject for MVP |

The recommended archive uses **ZIP STORE** (no ZIP-level recompression) because print PNGs are already losslessly compressed. The ZIP member's payload must exactly equal the fetched verified public PNG bytes. Archive compression setting may change ZIP size; it must never change the member bytes. Watermarked `preview.webp` and low-resolution `thumb.webp` are display-only, never print or archive inputs.

## Static manifest and source of truth

Candidate editorial manifest kept under separately reviewed source control (schema sketch, **not** currently created or published):

```json
{
  "schema": "ausmalwiese.bundle.v1",
  "id": "tiere-starter-v1",
  "title": "Tiere zum Ausmalen",
  "language": "de",
  "access": "free",
  "activity_ids": ["<existing-reviewed-id-1>", "<existing-reviewed-id-2>"]
}
```

Example IDs are placeholders, **not** evidence of published content. The manifest preserves ordered activity IDs and does not contain arbitrary third-party file paths. The trusted packer, if independently authorized later, would fetch the **fresh canonical RPi5 production catalogue** and expand each chosen activity into its actual ordered `pages[].print` URLs (or the legacy top-level `print` when no `pages[]` exists). Enforce a **total sheet count** of exactly the separately approved pack size; never silently discard part of a multi-page activity.

Never interpolate titles, request parameters, or arbitrary URL strings into filesystem paths. Only accept approved catalogue IDs, known canonical `/media/<id>/...` print paths and files constrained inside the expected public media root (including symlink/path traversal checks). Use source-derived sequential ASCII member names, e.g. `01-1234567-01.png`, and avoid duplicates. Read and hash each existing PNG; validate nonzero bytes, PNG signature and current A4 print contract **without resizing**. Treat any missing page, mixed sheet count, hash mismatch, unknown license or disallowed path as a **pre-publication STOP**; don't offer an incomplete ZIP.

Build into a temporary location, verify archive readability, member order, every PNG's SHA-256/bytes against the pre-pack snapshot and no additional files, then promote a **content-addressed immutable archive** (and a signed-off, non-sensitive inventory containing ID, count, member checksums, total bytes, archive checksum and review provenance) through a separately authorized publication route. No overwrite, silent delete or automatic retention policy implied. Publish a normal link only after public HTTP 200, byte-size/hash and full-member round-trip verification. If any referenced page is later unpublished, hide/withdraw the corresponding bundle through a separately authorized procedure; an immutable ZIP could otherwise remain accessible even though the activity disappeared from `catalog.json`.

## Performance and cost — sizing before implementation

The A4 source standard is **2480 × 3508** portrait (or **3508 × 2480** landscape), about **8.70 million pixels**. Decoded RGB requires `2480 * 3508 * 3 = 26,099,520 bytes` (**24.89 MiB**) **per image**; RGBA canvas buffers can take **33.19 MiB** per sheet. Thus 10 decoded RGB sheets use at least **249 MiB**, and 30 about **747 MiB**, before thumbnails, ZIP input buffers, Blob output, printing canvases and browser overhead. This is why decoding 10–30 sheets in a phone browser is not a safe default.

PNG file sizes depend on artwork and encoder. These are **hypothetical transfer scenarios, not measured production sizes**:

| Compressed PNG per sheet | 10-sheet ZIP STORE payload, approximately | 30-sheet payload, approximately |
| --- | --- | --- |
| 0.5 MB | 5 MB | 15 MB |
| 5 MB | 50 MB | 150 MB |
| 15 MB | 150 MB | 450 MB |

ZIP headers add small overhead; server egress for `N` downloads is approximately `N * archive bytes`, excluding CDN cache hits and retries. Before GO to actual packaging, collect **real** live `print.png` byte sizes (minimum, p50, p95, maximum) across portrait, landscape and multi-page records; measure archive size, build time, cold/warm public download timing, CDN caching, disk growth and traffic costs. Budget mobile data and failures, not just typical desktop broadband. No production measurements have been performed in this research step.

Browser ZIP research: JSZip documents that `generateAsync()` holds a full result in memory, requiring caution for large files. If browser implementation is later approved, pin/audit its dependency locally, use binary buffers and `STORE`, bound concurrency, provide progress/cancel and integrity validation, and revoke temporary Blob URLs after the download is safely handed off. No remote CDN JS bundle by default. Sources: https://stuk.github.io/jszip/documentation/limitations.html and https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static .

## User interface — German copy (future, not installed)

Mobile-first, heading then short text, 2–4 small **preview-only** thumbnails, an explicit download size calculated from the built archive (never guessed), and a fallback to individual pages. The CTA is a standard link to an immutable ZIP path, **only when public verification has succeeded**, not a misleading dead button. Keyboard-focus and status text should be visible without relying on color or pointer hover.

> **Tiere zum Ausmalen**  
> 10 A4-Malvorlagen als PNG – kostenlos. Alle Motive kannst du auch einzeln ansehen und ausdrucken.  
> **PNG-Paket als ZIP herunterladen**  
> **Malvorlagen einzeln ansehen**

If the ZIP is not available, show only the individual-page flow with an honest status: **„Das Paket ist zurzeit nicht als ZIP verfügbar. Du kannst die Malvorlagen einzeln öffnen und ausdrucken.“** Avoid prices, marketing countdowns, cookie banners or age claims not supported by selected metadata. Do not imply that selecting a ZIP also starts a combined print job.

## Legal and operational gates

**Free set: conditional GO only after editorial/provenance review.** Verify original ownership/licensing for every image, third-party provenance, the site's current permitted family/Kita use and whether redistributing full-quality images as a consolidated archive is allowed. Do not infer resale, commercial redistribution or relicensing rights from "free to print". ZIP availability does not prevent copying or "Save as"; make no DRM or anti-copy promises. Do not include children's artwork, identity or user uploads.

**Paid downloads: NO-GO for #197.** Separate approval and German/EU legal, financial, payment-provider and consumer review would be required before pricing or checkout: contractual disclosures, terms/licensing, `BGB §356(6)` (paid digital content withdrawal-right expiry needs explicit consent, acknowledgment and confirmation under `§312f`), invoice/VAT/accounting, refund/support, data protection, transaction retention, security/fraud and fee economics. **Starting a download alone does not automatically remove withdrawal rights.** This is an issue gate, not a statement that project compliance already exists. Official references: https://www.gesetze-im-internet.de/bgb/__356.html and https://www.gesetze-im-internet.de/bgb/__312f.html .
